# Art sets (MSX2 original / MSX1 / remaster)

> Golden rule: **art is a folder, not code.** For a "Remaster" to show up in the menu you just need to
> create `Content/ArtSets/<id>/` with an `artset.json`. Not a single line of C# changes.

## What a set is

| Set | Folder | Id | Pipeline (`flavor`) |
| :--- | :--- | :--- | :--- |
| MSX2 (the longplay original) | `Content/Rom` | `msx2` | `msx2` |
| MSX1 (the RC-760 cartridge original) | `Content/RomMsx1` | `msx1` | `msx1` |
| Remaster (whatever you make) | `Content/ArtSets/<id>` | `<id>` | whatever the manifest says |

The **pipeline** is not "which drawing": it is how the game assembles the scene.
`msx2` assembles the room from the blocks/murals and draws the 20 px HUD; `msx1` uses the room screens
dumped from the cartridge (256×192, no HUD band). A remaster picks which of the two to follow.

## Creating a remaster

```
Content/ArtSets/remaster/
    artset.json              ← manifesto (opcional, mas recomendado)
    Art/kv2.atlas            ← atlas de sprites/tiles (formato do Nez)
    Art/Screens/title.bin    ← telas fixas que você refizer
    Rooms/                   ← só se o flavor for msx2 e você refizer a montagem
```

`artset.json`:

```json
{
  "name": "Remaster",
  "flavor": "msx2",
  "base": "msx2"
}
```

| Field | Default | Role |
| :--- | :--- | :--- |
| `name` | id in uppercase | text of the **GRAPHICS** line in the system menu |
| `flavor` | `msx2` | `msx2` or `msx1` (room/HUD pipeline) |
| `base` | `msx2` | set the missing files come from |

**You do not have to redo everything.** Each file is looked up first in the active set and, if it does
not exist, in `base` (and in *its* `base`, up to 8 hops). Real example: a pack with **only**
`Art/Screens/title.bin` works — the atlas, the rooms and the rest come from MSX2.

A set only shows up in the menu if it has `Art/` (an empty folder is ignored).

## Choosing in the game

- **System menu** (`ESC` during the level) → `GRAPHICS` (`←`/`→` cycles MSX2 → MSX1 → remaster…`).
- **F11** cycles directly.
- The choice goes to the save (`GfxRom: "<id>"`).
- `KINGSVALLEY_GFX=<id>` forces it at boot (diagnostics/CI) and takes precedence over the save.
- If the saved set does not exist on disk, the game falls back to the first available one (that is how
  the free build, without `Content/Rom`, opens on `msx1`).

## Art formats

| What | Format | Who reads it |
| :--- | :--- | :--- |
| Fixed screens | `.bin`: 32 B of palette (16 colors, `(R<<4)\|B`, `G`), 2 B width, 2 B height, 1 B flags, 1 B reserved, 4bpp bitmap | `ScreenAssembler` → `ScreenBuilder` |
| Sprites/tiles/UI | `.atlas` (libGDX, padding + extrusion) | `SpriteAtlasLoader` |
| Room (msx2) | `Rooms/` (4bpp blocks, murals, decorations, palettes) | `RoomAssembler`/`RoomBackgroundBuilder` |
| Room (msx1) | room screens already assembled as `.bin` | `RoomBackgroundBuilder` |

> ⚠️ **PNG is not a game format.** No background/screen in PNG: everything is assembled at runtime
> (see the rule in `AGENTS.md`). PNG only exists inside the `.atlas` (packed texture) and as a
> **reference** generated by a tool.

### Viewing the screens outside the game (reference)

### Remaster kit: PNG ⇄ .bin (round trip)

The artist **paints PNG**; the game reads `.bin`. `tools/kv2-extract/art/artkit.py` converts both ways
(the sprite atlas is already PNG: `Art/kv2.png`).

```bash
cd tools/kv2-extract

# 1. cria o pacote (aparece no GRAPHICS do system menu)
python art/artkit.py pack ../../src/KingsValley.Desktop/Content/ArtSets/remaster --name "Remaster" --base msx2

# 2. exporta a arte atual para PNG (base para pintar por cima) — 2x para trabalhar confortável
python art/artkit.py export ../../src/KingsValley.Desktop/Content/Rom/Art/Screens remaster-src --scale 2

# 3. ...pinta os PNG em Aseprite/Photoshop/GIMP (cada tela vem com um .gpl da paleta)...

# 4. importa de volta só o que mudou
python art/artkit.py import remaster-src ../../src/KingsValley.Desktop/Content/ArtSets/remaster/Art/Screens
```

Rules the kit guarantees:

| Item | Behavior |
| :--- | :--- |
| Size | the `.json` next to the PNG stores the real size; exporting at 2x/3x and importing goes back to the right size (no blurring: nearest-neighbor resampling) |
| Palette | uses the original palette from the `.json` (order preserved) and **snaps to the nearest color** for whatever the artist painted anew |
| No `.json` (new screen) | uses the exact colors up to 16; above that it quantizes (median cut) |
| Round trip without editing | **visually identical** (0 differing pixels across the game's 14 screens) |

> ⚠️ The round trip is not *byte for byte* when the palette has repeated colors (the TMS has black at
> indices 0 and 1): the PNG cannot tell "black 0" from "black 1", so the indices may regroup. The
> rendered image is the same — that is what matters for the art.

**Sprites/UI:** edit the pack's `Art/kv2.png` (same atlas layout) or pack a new one with
`tools/pack_atlases.ps1`. The `.atlas` describes the rectangles; if you change the layout, regenerate the
atlas and copy both (`kv2.png` + `kv2.atlas`) into the pack.

To just *look* at the screens extracted from the ROM:

```bash
python art/artkit.py export "%APPDATA%/KingsValley/extracted/Screens" preview --scale 2
```

## In the free build (public version)

The free build does not ship **anything** derived from Konami: on first boot it extracts from the
player's ROM (`%APPDATA%\KingsValley\extracted\`) the levels, the audio and the fixed screens.
Consequences:

- only the `msx1` set exists (it is what the MSX1 ROM allows extracting exactly);
- screens are looked up first in `extracted\Screens` (`ArtSet.ExtractedFirst`);
- a remaster in the free build must declare `"base": "msx1"`: whatever it lacks falls back to the art
  extracted from the ROM (which is where the `msx1` set points). With `"base": "msx2"` there is nowhere
  to fall back to, because the free build does not ship MSX2;
- to export/paint the free build's art, use the extracted folder as the source:
  `python art/artkit.py export "%APPDATA%/KingsValley/extracted/Screens" remaster-src --scale 2`.
