# Architecture — King's Valley 2 (clone)

Three layers, with the **golden rule**: the **rules** are synchronous, deterministic and testable without
opening a window; the **Engine** only animates/draws what the Core decided.

```text
┌──────────────────────────────────────────────────────────────────────┐
│ KingsValley.Desktop   Entry point + Content (Gum, atlas, áudio)       │
├──────────────────────────────────────────────────────────────────────┤
│ KingsValley.Engine    Nez + Gum: cenas, render, input, UI             │
├──────────────────────────────────────────────────────────────────────┤
│ KingsValley.Core      C# puro: grade, sessão, regras, save            │  ← ZERO gráficos
└──────────────────────────────────────────────────────────────────────┘
```

---

## 1. Data flow (one tick = 1 ROM logic call, ~30 Hz like the original)

```text
Content/Rom/Levels/stageNN.json  (extraído da ROM por tools/kv2-extract)
   │  StageLoader.Load
   ▼
StageDefinition (Core, imutável)  ──►  StageSession (Core): salas (RoomMap), jogador, inimigos,
   ▲                                    itens, soul stones, porta → lista de GameEvent por tick
   │ GameRun (stage, REST, score, hiscore, senha)
GameScene (Engine) ──► PlayerInput (teclado) ──► StageSession.Tick ──► GameEvents
   │                                                                      │
   ├─ RoomRenderer: mural + tiles + objetos + personagens + HUD (atlas kv2)│
   └─ GameAudio: música do stage + efeito de cada evento ◄────────────────┘
```

- The Core **never** knows about textures, cameras or input — only 8x8 cells, pixels and rules.
- The Engine **never** decides a rule — it translates the keyboard into `PlayerInput`, draws and plays sounds.
- Tests (`tests/KingsValley.Core.Tests`): measured physics, passwords, tools, knife, ladder, rooms,
  progression — and loading/simulating the 60 real stages when `Content/Rom` exists.

## 2. Scenes and navigation

```text
Splash ──► MainMenu ──ENTER──► Loading ──► Game (sala) ──completou──► Game (próxima)
                                  │                                       │
                                  └── passos fatiados (LoadStep)          └── Esc ──► MainMenu
```

- **`GameNavigation`** is the **single point** for scene changes (`GoTo`, `GoToLoading`, `GoToLevel`).
- **`SceneBase`** separates `Initialize()` (runs in the base constructor — resolution/camera) from
  `OnStart() → OnInitialize()` (content; the constructor fields already exist).
- **Sliced loading**: `LoadStep` + a budget of ~6 ms/frame (the `GraphicsDevice` is not thread-safe).

## 3. Render layers (3 levels)

```text
┌─ PostUiOverlay ── HUD de debug, flash de tela, texto flutuante, cursor (acima da UI)
├─ Gum UI ────────── menus, HUD, diálogos (sempre acima da cena)
└─ Cena (Nez) ────── RenderLayers (Background 1000 ... ScreenFx -50)
```

| You need | Where |
| :--- | :--- |
| Game object (tile, player, enemy, effect) | Nez entity + `RenderLayers` |
| Interface (menu, HUD, dialog) | **Gum** (never `Nez.UI` in new code) |
| Above the UI (cursor, flash, floating text) | **`PostUiOverlay`** |

> In Nez, **lower `RenderLayer` = more in front**. A `SpriteRenderer` is **never** above the UI.

## 4. Resolution and coordinates

| Aspect | Value |
| :--- | :--- |
| Policy | `SceneResolutionPolicy.None` (RT = backbuffer, blit 1:1) |
| Coordinate space | **design units** — MSX2 screen 256x212 (32x24 cells of 8 + 20 of HUD) |
| Binding | `zoom = BackBufferHeight / 212f` (filter `PointClamp`) |
| Camera | `DesignViewportCamera` (`Camera.RawZoom = DesignViewport.Scale`) |
| Gum | `Renderer.Camera.Zoom = zoom`; `CanvasWidth/Height = BackBuffer / zoom` |

So **world and UI share the same space**: a tile at `x = 64` lines up with a Gum element at
`x = 64`. Never go back to `FixedHeight` (it renders at a fixed height and **stretches**, blurring).

> The window can be larger (1024x768, 1920x1080) — the zoom compensates and the game stays **pixel-perfect**
> at an integer scale (or bilinear, depending on the art).

## 5. Assets and lifecycle

| Scope | Where | Release |
| :--- | :--- | :--- |
| **Global** (atlases) | `GameAssets` | `GameAssets.Unload()` on shutdown |
| **Scene** (background, UI) | `SceneBase.Own(...)` / `LoadTexture(...)` | automatic in the scene's `Unload()` |

> ⚠️ `Texture2D.FromStream` is **not** tracked by any ContentManager — always go through
> `SceneBase.LoadTexture`/`Own`, otherwise it leaks VRAM on every scene change.

**Atlas** (all sprite art):
- Generated by `tools/pack_atlases.ps1` (libGDX `.atlas`), `padding ≥ 2` **with extrusion**,
  `rotation`/`trim` **OFF**.
- **Two atlases per blend**: Gum UI → `premultiplyAlpha: false`; scene → `true`.
- **Art bound by NAME** (the `.gusx` does not store coordinates) → repacking never breaks the UI.

## 6. Save

`SaveGameData` (versioned) + `ProfileSaveService` (pure C#, atomic write) in
`%AppData%/GreenSauceGames/King's Valley 2/save.json`. It stores settings (language, cursor, fullscreen)
and progress (highest room, completed rooms, score).

## 7. Where to add each thing

| New thing | Where |
| :--- | :--- |
| New rule/tile/mechanic | `KingsValley.Core/World` (+ test in `tests`) |
| New room | `KingsValley.Core/World/LevelLibrary.cs` (ASCII) or `Content/Levels/*.json` (future) |
| New world visual | `KingsValley.Engine/Scenes/GameScene.cs` (`GameView`) + `RenderLayers` |
| New screen/dialog | `Content/Gum/Screens/*.gusx` + code in `Engine/UI/Gum` |
| New effect above the UI | `Engine/UI/*` (`ScreenOverlay`) |
| New atlas | `tools/kv2-extract/art` (generates `Content/Rom/Art/kv2.atlas`) + `GameAssets` |
